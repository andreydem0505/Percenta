Percenta — ИСХОДНИКИ И ЗАМЕНА HEIC-КОМПОНЕНТА

Компоненты: heic-to 1.6.6 (Hopper Gee), libheif 1.23.6, libde265 1.0.16
(Dirk Farin/struktur AG и участники проектов). Применяются оригинальные LGPL/GPL.
См. /legal/third-party.txt и /legal/licenses/.
Компоненты предоставлены без гарантии в пределах применимой лицензии.

Модуль /vendor/heic/heic-to.mjs — неизменённый dist/next/heic-to.js из npm heic-to.
Он загружается по относительному адресу только при выборе HEIC в отдельном worker.
Vite не включает этот файл в JS приложения или worker. Нет SRI, подписи, проверки
хеша в браузере или иной технической блокировки совместимой изменённой библиотеки.
Проверка оригинального SHA-256 выполняется только при подготовке официальной сборки.

КАК ЗАМЕНИТЬ ГОТОВЫЙ МОДУЛЬ БЕЗ ПЕРЕСБОРКИ ПРИЛОЖЕНИЯ
1. Получите копию статической сборки Percenta для локального размещения.
2. Замените в ней vendor/heic/heic-to.mjs своим совместимым ES-модулем.
3. Он должен экспортировать async heicTo({blob, type:'image/png'}): Promise<Blob>.
   Вход — File/Blob, выход — корректное PNG-изображение. Выполнение — в Web Worker.
4. Запустите статическую сборку на HTTP(S), например через npm run preview, затем
   полностью перезагрузите страницу и загрузите HEIC. Worker подхватит новый файл.
Изменения исходников главного приложения и его пересборка для замены не нужны.
Кэширование этого стабильного пути настроено с revalidation, без immutable.
Не запускайте копию через file:// — для ES-модулей нужен локальный HTTP-сервер.
Для своего рабочего экземпляра публичного сайта можно использовать локальную
копию/перехват ресурса браузером; доступ к серверу автора для этого не требуется.

КАК ПЕРЕСОБРАТЬ ИЗ JS-ИСХОДНИКОВ
1. В checkout Percenta выполните npm ci (Node.js 22.18+).
2. Распакуйте heic-to-1.6.6.tar.gz в доступную папку; измените src/ по необходимости.
3. Выполните:
   node scripts/vendor/rebuild-heic.mjs /путь/heic-to-1.6.6 /путь/к/сборке/vendor/heic/heic-to.mjs
   Если сборка лежит в dist, последним аргументом будет dist/vendor/heic/heic-to.mjs.
4. Снова запустите статический сервер/preview и загрузите HEIC.
Скрипт использует esbuild из зафиксированного окружения проекта и повторяет
upstream-композицию worker + src/next/index.js. Это не проверка побитовой
воспроизводимости Emscripten-выхода C/C++.

КАК ИЗМЕНИТЬ C/C++ ДЕКОДЕР
Распакуйте два C/C++ архива. Сборочный рецепт upstream находится в heic-to/README.md
и libheif/build-emscripten.sh; исходный src/lib/libheif.js явно указывает
libheif 1.23.6 и LIBDE265_VERSION=1.0.16. Нужны Emscripten SDK, CMake, make,
autoconf/automake/libtool/pkg-config. Используйте рецепт upstream:
  mkdir buildjs
  cd buildjs
  LIBDE265_VERSION=1.0.16 USE_WASM=0 /путь/libheif-1.23.6/build-emscripten.sh /путь/libheif-1.23.6
Скрипт upstream принимает окружение; для macOS при необходимости задайте CORES=4.
Распакованный libde265 и его tar.gz можно поместить в buildjs с ожидаемыми именами,
чтобы использовать локальную копию исходников вместо повторного скачивания.
Замените сгенерированным libheif.js файл heic-to/src/lib/libheif.js, сохранив
форму экспорта из исходного файла, и выполните JS-пересборку выше.
Оригинальный recipe содержит платформенные особенности; полный C/C++ цикл
в окружении проекта не выполнялся. Пользовательские изменения не обязаны
поддерживаться автором Percenta, права по LGPL при этом сохраняются.
