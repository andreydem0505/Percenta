# Контекст проекта для ИИ-агента

## Назначение

Percenta — русскоязычное приложение для хранения категорий кэшбека разных банков. React 19, TypeScript, Vite, Tesseract.js, heic-to, lucide-react. Статический сайт без серверной части, регистрации и облачной базы. Пользовательские записи хранятся в localStorage; скриншоты не сохраняются и не передаются внешним сервисам. Пользователь явно запросил Google Analytics через Firebase: это отдельная необязательная интеграция, описанная ниже. Не добавляйте облачный OCR или другие внешние сервисы без явного запроса пользователя.

Пользовательская задача — перед покупкой выбрать подходящую карту по своим предложениям банков. Основной сценарий: указать банк и загрузить скриншот категорий → проверить распознанное → сравнить предложения по нужной категории → при необходимости перейти в банк с телефона. Альтернативы — ручной ввод и перенос сохранённого набора файлом. Percenta не подключается к банковским аккаунтам, не загружает условия из банков автоматически, не рассчитывает гарантированную выгоду с учётом MCC/лимитов и не синхронизирует записи между устройствами. Не обещать эти возможности в описаниях.

## Необязательная аналитика Firebase

`src/features/analytics/` содержит проверку конфигурации, браузерный адаптер и компактное всплывающее уведомление, закреплённое у нижнего края экрана независимо от прокрутки. На компьютере оно справа, на телефоне занимает ширину с боковыми отступами и учитывает safe area. Уведомление не блокирует сайт. По прямому запросу владельца от 24.10.2026 выбор разрешения/отказа заменён уведомлением «Используя сайт, вы соглашаетесь с использованием cookie Google Analytics» с одной кнопкой «Понятно». По уточнённому поручению владельца аналитика включается при каждом посещении production HTTPS-сайта независимо от старых отказов и доступности localStorage; закрытие уведомления не включает и не выключает сбор. Отметка просмотра хранится в `percenta.analytics-notice.v1`, синхронизируется между вкладками и не попадает в экспорт. Это только факт закрытия уведомления, не доказательство согласия. Старый ключ `percenta.analytics-consent.v1` больше не читается и не перезаписывается, его значения не управляют сбором. Ошибки чтения/записи Storage влияют только на повторный показ уведомления; закрыть его можно на текущее посещение даже при ошибке записи. В интерфейсе нет отказа или отзыва разрешения. Нельзя гарантировать доставку каждого события: сеть, блокировщики, ограничения браузера и неподдерживаемое окружение могут её прервать. Не обходить эти ограничения.

Используются только официальные `@firebase/app` и `@firebase/analytics`, SDK загружается динамически. Повторные эффекты StrictMode не должны создавать дубли просмотров. Контроллер сохраняет возможность немедленно выключить сбор, включая асинхронную инициализацию; блокировщики и ошибки не мешают приложению. Удаление кнопок не отменяет правовых требований: уведомление о продолжении использования само по себе не подтверждает отдельное информированное согласие по ст. 9 152-ФЗ. Google также описывает возможность разрешить/запретить сбор в своих требованиях к приватности Analytics. Владелец предупреждён об этом риске; не объявлять текущую модель юридически проверенной, не записывать автоматически `granted` и не выдавать нажатие «Понятно» за согласие.

Сбор включается только при `VITE_ANALYTICS_ENABLED=true`, полной конфигурации `VITE_FIREBASE_*`, production-сборке, HTTPS и не на localhost. Шаблон — `.env.example`; реальные публичные параметры веб-приложения находятся в игнорируемом `.env.local`, переменные Vite попадают в клиентскую сборку и не являются секретами. Не помещать сюда ключ сервисного аккаунта, токены или приватные ключи. Смена параметров требует пересборки. В CI и на новом хостинге нужно отдельно задать переменные: `.env.local` не попадает в Git.

**Перед включением выключить Enhanced measurement («Улучшенная статистика») в GA → Администратор → Потоки данных → нужный веб-поток.** Это выбранная для проекта мера минимизации данных, а не обязательное требование Firebase. Эта настройка сервера может включать автоматический сбор кликов, поиска, имён файлов и форм, её нельзя считать отключённой только по отсутствию `logEvent` в коде. 24.10.2026 владелец подтвердил отключение и поручил включить аналитику: в локальном `.env.local` установлен `VITE_ANALYTICS_ENABLED=true`. Пример окружения по умолчанию оставлен выключенным. Деплой этим поручением не запрошен. Не добавлять Tag Manager/gtag параллельно SDK: возможны дубли и обход согласия.

Передаются стандартная статистика посещения и технические идентификаторы Firebase/GA; приложение задаёт фиксированные `page_location` (origin + `/`), `page_title`, пустой `page_referrer`, отключает Google signals и рекламную персонализацию, задаёт cookie 90 дней без продления. Не добавлять пользовательские банки, категории, проценты, скриншоты, OCR-текст, поиск и JSON ни в события, ни в user properties/ID/URL. Уведомление называется «Cookie для статистики»; в справке оставлена только ссылка «Приватность», настройки cookie удалены по запросу владельца. Google получает технические данные за пределами локального устройства; согласие не гарантирует выполнение российских требований локализации и трансграничной передачи. Не обещать российское хранение или полную анонимность. При изменениях обновлять `/legal/privacy.html`.

Пакеты Firebase не поставляют общий LICENSE в каждом npm-подпакете. Для шести проверенных версий в `scripts/legal/prepare.mjs` явно указан upstream LICENSE из firebase-js-sdk 12.19.0, закреплённый SHA-256 в `vendor/manifest.json`. При обновлении версий повторно проверить происхождение/лицензии, не расширять исключения автоматически.

В robots.txt разрешены JS/CSS и шрифты; запрещены только технические OCR/банковские изображения, метки переходов перечислены в Clean-param. ## Команды

Нужны Node.js 22.18+ и npm. В корне репозитория:

```sh
npm ci
npm run dev
npm run typecheck
npm test
npm run test:ocr
npm run build
npm run test:licenses
npm run format:check
```

`npm ci`, `npm run dev`, `npm run test:ocr` и сборка подготавливают локальные ресурсы OCR/HEIC и комплект лицензий. `npm run preview` показывает собранный `dist/`. `npm run format` форматирует исходники, тесты и документацию. `npm run test:fixtures` пересоздаёт синтетические изображения; настоящий HEIC генерируется через macOS `sips`, если он доступен. Готовые фикстуры уже включены в репозиторий, поэтому обычные проверки работают и на Linux.

## Структура и границы ответственности

- `src/app/` — точка композиции приложения, диалоги, уведомления и координация пользовательских операций. `App` связывает компоненты и внедряет реализацию хранилища.
- `src/features/offers/model/` — типы, валидация, обновление и сортировка предложений; здесь же контракт `OfferRepository`. Бизнес-правила не зависят от DOM или localStorage.
- `src/features/offers/data/` — адаптер localStorage и подписка на изменения из других вкладок. Доступ к Storage отложен до чтения/записи, чтобы запрет браузера обрабатывался как обычная ошибка.
- `src/features/offers/hooks/` и `components/` — фильтры и интерфейс списка/ручного ввода.
- `src/features/banks/` — локальные JSON-справочники, сопоставление названий, логотипы и ссылки в банковские приложения. `model/` содержит правила, `services/` — работу с настройками браузера.
- `src/features/recognition/` — чистый парсер OCR и обработка пикселей в `model/`, браузерные адаптеры в `services/`, отдельный HEIC worker в `workers/`, управление отменой и этапами в `hooks/`, форма проверки в `components/`.
- `src/features/backup/` — чистый формат JSON и объединение в `model/`, файловые операции в `services/`, отменяемое чтение в `hooks/`, предпросмотр в `components/`.
- `src/features/analytics/` — проверка условий включения в `model/`, ленивое подключение Firebase и отзыв разрешения в `services/`, автоматический запуск и сохранение/синхронизация закрытия уведомления в `hooks/`, информационный блок cookie в `components/`. Этот модуль не получает записи кэшбека и OCR-данные.
- `src/shared/` — независимые общие компоненты, базовые стили, определение мобильной версии и генератор ID.
- `scripts/banks/` — явное обновление банковских справочников. `config/` содержит правила сопоставления; `provenance/` — происхождение данных и ограничения проверки ссылок.
- `scripts/ocr/` — подготовка локальных ресурсов, проверка OCR и генерация тестовых изображений.
- `tests/fixtures/` — синтетические картинки и минимальные выдержки источников банковских ссылок. Оригиналы личных скриншотов сюда не добавлять.
- `docs/screenshots/` — настоящие скриншоты приложения с демонстрационными данными для README.

Соблюдайте принципы SOLID через небольшие контракты и композицию функций, а не через классы ради классов. Чистые правила находятся в `model/`, браузерные эффекты — в адаптерах, React-состояние — в хуках, отображение — в компонентах. `useOffers` принимает `OfferRepository`; `App` также принимает `AnalyticsController` для проверки cookie без обращения к Google, OCR-хук принимает `ScreenshotServices`; чтение JSON можно подменить через контракт функции. Не возвращайте сохранение, распознавание и обработку файлов в `App` или JSX-компоненты. Общие модули не должны зависеть от функциональных модулей. Межмодульную координацию размещайте в `app/`. Стили разделены по тем же зонам ответственности; точка подключения — `src/app/styles.css`. Не добавляйте слои CSS-переопределений в конец общего файла.

## Правила предложений

- Каждая запись: `id`, `category`, `bank`, `percent`. Категория и банк обязательны, максимум 120 и 80 символов соответственно; процент — конечное число от 0 до 100. Ручной ввод поддерживает точку/запятую и до двух знаков после разделителя.
- Показывать **все** предложения, включая менее выгодные предложения той же категории в другом банке. Прежнее поведение «только максимальный процент» удалено и не должно возвращаться.
- Пара «банк + категория» сравнивается без регистра и лишних пробелов. Повторное добавление обновляет процент, сохраняя ID. Синонимы категорий и разные варианты имён банков в самих записях автоматически не объединять.
- Предложения на все покупки закреплены наверху и выделены цветом. Остальные предложения идут по убыванию процента; переключатель сортировки удалён по решению владельца. Распознавание формулировок — `src/features/offers/model/categories.ts`; сохраняйте отрицательные примеры вроде «Все супермаркеты» и «Всё для дома».
- Один актуальный набор; нет истории, автоматического истечения срока или очистки при смене месяца.
- Удаление одной записи не меняет другие предложения категории. Полная очистка требует диалога подтверждения.

## Хранилище и перенос JSON

Ключ записей — `cashback.offers.v1`, формат `{ "version": 1, "offers": [...] }`. Не менять ключ или формат без миграции. UI обновляется только после успешной записи. Если исходное хранилище повреждено/недоступно, не затирать его при добавлении или импорте: разрешены повторное чтение или явная очистка. Внешнее событие `storage` перечитывает набор; после ошибки чтения сохранение блокируется.

Экспорт включает все сохранённые предложения, независимо от поиска, только поля формата. Если сохранённых предложений нет, «Скачать JSON» имеет нативный `disabled` и не запускает скачивание; предпросмотр ещё не подтверждённого импорта не включает экспорт. Сам импорт при пустом наборе остаётся доступным. Импорт проверяет весь файл, затем показывает предпросмотр; запись происходит по подтверждению. Неверный JSON/версия/поля/процент или повтор ID отклоняют весь файл. Ограничения — 5 МБ и 10 000 предложений. UTF-8 BOM поддерживается. Импорт объединяет пары; последнее вхождение пары в файле побеждает. Пустой файл не очищает набор. При конфликте ID разных пар назначается новый ID; повторный импорт не создаёт дубликаты. Скриншоты и настройки запуска банков в резервную копию не включаются.

`createId` поддерживает обычный HTTP на телефоне в локальной сети, где `crypto.randomUUID` может отсутствовать. Не удаляйте резервный вариант на `crypto.getRandomValues`.

## Распознавание скриншотов

Поддерживаются PNG, JPEG, WebP, HEIC/HEIF до 25 МБ, включая пустой MIME и проверку сигнатуры HEIC. Выбор файла не должен принудительно открывать камеру. Внешний для bundle, но локальный для сайта `/vendor/heic/heic-to.mjs` — точная копия `heic-to/next` 1.6.6; worker импортирует её через `@vite-ignore` только при необходимости. Не возвращать обычный runtime import из npm: это снова объединит LGPL-код с приложением. Только type-import допустим. Конвертер не переносить в главный JS-пакет или worker bundle; worker должен завершаться при отмене и ошибке.

Совместимый HEIC-модуль можно заменить после сборки без пересборки приложения. Не добавлять SRI, runtime SHA/подпись и immutable-кэш на этот путь. Права на замену/отладку и источники адаптера указаны в `/legal/heic-replacement.txt`. `scripts/vendor/rebuild-heic.mjs <source-folder> <output.mjs>` собирает модуль из upstream JS-исходников; npm ci устанавливает нужное окружение. Свою изменённую библиотеку заменяют в dist после build: prepare проверяет оригинал при официальной сборке. Не считать такую build-time проверку запретом пользовательской замены.

Tesseract использует русские и английские данные с адреса приложения (`public/ocr/`), которые копирует `scripts/ocr/prepare.mjs`. Облачных вызовов нет. OCR загружается динамически. Холст ограничивается 2400 пикселями по длинной стороне; для тёмных экранов используется `PSM.AUTO`, для светлых списков/сеток — `PSM.SPARSE_TEXT`. Предобработка и тестовый CLI используют одну функцию обработки пикселей. Парсер учитывает расположение слов и процентов, сетки, заголовки, дробные значения и символы возле процентов.

Перед сохранением пользователь всегда проверяет и исправляет строки. Отсутствие текста и ошибка распознавания оставляют ручной ввод доступным. Отмена, повторный выбор и закрытие формы должны игнорировать запоздалые результаты; тайм-ауты преобразования/распознавания — 60/120 секунд. Освобождать Blob URL, холсты, worker и обработчики.

## Банки, логотипы и диплинки

Справочники локальные: 300 действующих банков и исторические названия/бренды, 360 WebP-изображений. Поиск использует полные имена и явные aliases, не произвольные подстроки. Не путать разные банки «АТБ»; регистрационный номер — стабильная идентичность. Не переименовывать пользовательские записи при подборе логотипа. При включённых логотипах неизвестный банк или ошибка картинки дают нейтральный значок; при текущем `BANK_LOGOS_ENABLED=false` скрыты и изображения, и этот значок.

Обновление выполняется только явно:

```sh
npm run banks:sync
npm run banks:apps:sync
```

Эти команды требуют интернет. Источники — ЦБ, НСПК, зафиксированная версия коллекции rblp и официальные сайты. Сведения по каждому изображению сохранены в `scripts/banks/provenance/catalog.json`, по ссылкам — в `scripts/banks/provenance/apps.json` и `scripts/banks/provenance/ios-apps.json`. Не запускать обновление источников автоматически при сборке или открытии приложения. Не удалять атрибуцию в `NOTICE`.

По запросу пользователя от 24.10.2026 банковские картинки отключены во всём интерфейсе, включая карточки и поля банка, без нейтральных значков вместо них. Все 360 оригиналов в `public/banks/`, справочники, компонент `BankLogo`, стили и проверки сохранены. Обычный `banks:sync` сохраняет текущие картинки; новые загрузки `--images` допускаются только по документированным разрешениям в `scripts/banks/config/logo-permissions.json` с нужным объёмом и сроком. Названия банков в карточках выделены мягкой цветной подложкой и приглушённым текстом. Цветовой тон вычислен по сохранённым логотипам без изменения файлов: `scripts/banks/generate-colors.mjs` читает локальные WebP, отбрасывает белый/чёрный/серый и усредняет доминирующий цвет. Результат — числовые тона по стабильным ID в `src/features/banks/data/bank-colors.json`; `src/features/banks/model/bank-colors.ts` подбирает их через существующие aliases. Подсветка сохраняется для предложений на все покупки и мобильных ссылок; она не меняет названия, данные и адреса приложений.

## Интерфейс и визуальная проверка

Пустая область «Пока нет категорий» принимает один скриншот перетаскиванием и подсвечивается при наведении файла. Она открывает обычный диалог загрузки с этим файлом: проверка формата/размера, HEIC, превью и отмена используют тот же `useScreenshotImport`, что и выбор файла. Банк вводится в диалоге; распознавание и сохранение требуют обычных действий пользователя. Несколько файлов отклоняются сообщением; текст и ссылки не принимаются. При закрытии диалога подготовка прерывается, файл не сохраняется. Кнопка загрузки в шапке остаётся доступной с клавиатуры и на телефоне.

Поля категории и банка используют общий `src/shared/ui/ClearableInput.tsx`: крестик виден только при непустом редактируемом значении, имеет область нажатия 44 × 44 px, очищает черновик и возвращает фокус без отправки формы. Это действует в ручной форме, поле банка при загрузке и строках проверки OCR. Подписи связаны с input явно через `htmlFor`/`id`; не помещать кнопку очистки внутрь `label`. Подсказки банков, ограничения длины и заблокированное состояние сохраняются.

В `BankInput` крестик стоит слева от отдельной стрелки выбора: справа через слот `trailing` расположен нативный `select` с полным списком банков. Он не фильтруется введённым названием и не очищает его при открытии; выбор обновляет то же текстовое поле. Встроенная стрелка `datalist` скрыта, сами подсказки при наборе сохранены. Не возвращать зависимость раскрытия полного списка от значения поля; при обработке блокируются и input, и select.

Справка объясняет пользу Percenta: собрать категории со скриншота банка или вручную, сравнить предложения перед покупкой и перенести сохранённый набор через «Данные». Сначала отвечать на вопрос «зачем сервис», затем кратко объяснять действия. Условия кэшбека проверяются в банке. Не перегружать справку деталями SDK, форматов хранения и лицензий. В справке есть подчёркнутая ссылка «Приватность» с областью нажатия не меньше 44 px по высоте. Настройки cookie удалены по запросу владельца.

Применён выбранный владельцем вариант «Графит»: фон #f2f3f4, белые поверхности, акцент #3c4857, спокойное выделение #e4e8ed, скругления 10 px и собственный знак со стопкой карт. Шрифт Onest (100–900) поставляется локально из `public/fonts/onest-variable.ttf`, без запросов к Google Fonts. Оригинальная OFL — `vendor/licenses/onest-OFL.txt`, происхождение/хеши — `vendor/manifest.json`; prepare и test:licenses проверяют файл и поставку лицензии. Структура экрана сохраняется. Не возвращать красно-жёлтую палитру и логотип-билет из прежнего дизайна.

Главный приоритет — немедленный доступ к категориям. Один экран, компактные карточки с категорией, процентом и банком; без рекламных баннеров, сводных счётчиков и дополнительных вкладок. Уведомление о cookie закреплено поверх страницы внизу экрана и видно без прокрутки; оно компактное, без затемнения фона, с одной кнопкой «Понятно». Не возвращать его в обычный поток после списка, где оно теряется на длинной странице. Поиск, добавление скриншота/вручную и кнопка «Данные» доступны на телефоне. Минимальная ширина — 320 пикселей без горизонтальной прокрутки; кнопки минимум 44 × 44, формы прокручиваются и не должны зависеть от высоты экранной клавиатуры.

Иконки категорий — локальные SVG из уже используемой Lucide, без внешних запросов. Чистый подбор по русским/английским формулировкам и окончаниям — `src/features/offers/model/category-icons.ts`; отображение — `src/features/offers/components/CategoryIcon.tsx`. Более точные правила стоят перед общими; учитывайте пересечения «корм для животных / продукты», «детское питание / продукты», «Самокат / самокаты», «домашний интернет / дом». Отдельные названия тарифов «Эконом», «Комфорт/Комфорт+», «Бизнес», «Премьер», «Элит», «Ultima/Ультима», «Круиз», «Минивэн» и их английские варианты получают иконку такси; допускается префикс «Тариф/Класс». Это точные названия, а не основы слов: «Экономика», «Комфортный отдых» и «Бизнес-услуги» не относятся к такси. Не сопоставлять по произвольной подстроке внутри слова. Для неизвестной категории — нейтральный Tag. Иконки декоративные (`aria-hidden`), название остаётся текстом. Подбор не переименовывает и не объединяет сохранённые категории; менять формат данных не нужно. Сохранять компактные размеры карточек и спокойную графитовую палитру. Иконки используют восемь приглушённых тонов со светлыми подложками (сланцевый, шалфейный, песочный, глиняный, лавандовый, голубой, розовый и бирюзовый); тон задан рядом со значком в `src/features/offers/components/CategoryIcon.tsx`, цвета — в `src/features/offers/components/offers.css`. Проверять `scrollWidth <= clientWidth`, включая длинные названия и дробные проценты.

Проверять 320, 375, 390 и настольную ширину, пустое состояние, длинные имена, диалоги, ошибки и предпросмотр. ## Проверки перед завершением изменений

После изменений логики/переносов запускать `npm run typecheck`, `npm test`, `npm run build` и `npm run format:check`. При изменениях распознавания, путей ресурсов или подготовительных скриптов — также `npm run test:ocr` (семь синтетических PNG/JPEG/WebP/тёмных/пустых примеров). Для браузерной проверки использовать отдельный локальный порт и только синтетические данные. Не читать и не перезаписывать реальный набор пользователя. После проверки удалять только созданные тестовые записи и закрывать временные вкладки. Не утверждать успешный нативный запуск по DOM href.
