# Контекст проекта для ИИ-агента

## Назначение

Aubenia — русскоязычное приложение для хранения категорий кэшбека разных банков. React 19, TypeScript, Vite, Tesseract.js, heic-to, lucide-react. Статический сайт без серверной части, регистрации, облачной базы, аналитики и API-ключей. Пользовательские записи хранятся в localStorage; скриншоты не сохраняются и не передаются внешним сервисам. Не добавляйте облачный OCR или запросы к внешним сервисам при обычной работе приложения без явного запроса пользователя; загрузка собственных статических ресурсов остаётся необходимой.

## Команды

Нужны Node.js 22.18+ и npm. В корне репозитория:

```sh
npm ci
npm run dev
npm run typecheck
npm test
npm run test:ocr
npm run build
npm run test:licenses
npm run format:check
```

`npm ci`, `npm run dev`, `npm run test:ocr` и сборка подготавливают локальные ресурсы OCR/HEIC и комплект лицензий. `npm run preview` показывает собранный `dist/`. `npm run format` форматирует исходники, тесты и документацию. `npm run test:fixtures` пересоздаёт синтетические изображения; настоящий HEIC генерируется через macOS `sips`, если он доступен. Готовые фикстуры уже включены в репозиторий, поэтому обычные проверки работают и на Linux.

## Структура и границы ответственности

- `src/app/` — точка композиции приложения, диалоги, уведомления и координация пользовательских операций. `App` связывает компоненты и внедряет реализацию хранилища.
- `src/features/offers/model/` — типы, валидация, обновление и сортировка предложений; здесь же контракт `OfferRepository`. Бизнес-правила не зависят от DOM или localStorage.
- `src/features/offers/data/` — адаптер localStorage и подписка на изменения из других вкладок. Доступ к Storage отложен до чтения/записи, чтобы запрет браузера обрабатывался как обычная ошибка.
- `src/features/offers/hooks/` и `components/` — фильтры и интерфейс списка/ручного ввода.
- `src/features/banks/` — локальные JSON-справочники, сопоставление названий, логотипы и ссылки в банковские приложения. `model/` содержит правила, `services/` — работу с настройками браузера.
- `src/features/recognition/` — чистый парсер OCR и обработка пикселей в `model/`, браузерные адаптеры в `services/`, отдельный HEIC worker в `workers/`, управление отменой и этапами в `hooks/`, форма проверки в `components/`.
- `src/features/backup/` — чистый формат JSON и объединение в `model/`, файловые операции в `services/`, отменяемое чтение в `hooks/`, предпросмотр в `components/`.
- `src/shared/` — независимые общие компоненты, базовые стили, определение мобильной версии и генератор ID.
- `scripts/banks/` — явное обновление банковских справочников. `config/` содержит правила сопоставления; `provenance/` — происхождение данных и ограничения проверки ссылок.
- `scripts/ocr/` — подготовка локальных ресурсов, проверка OCR и генерация тестовых изображений.
- `tests/fixtures/` — синтетические картинки и минимальные выдержки источников банковских ссылок. Оригиналы личных скриншотов сюда не добавлять.
- `docs/screenshots/` — настоящие скриншоты приложения с демонстрационными данными для README.

Соблюдайте принципы SOLID через небольшие контракты и композицию функций, а не через классы ради классов. Чистые правила находятся в `model/`, браузерные эффекты — в адаптерах, React-состояние — в хуках, отображение — в компонентах. `useOffers` принимает `OfferRepository`; OCR-хук принимает `ScreenshotServices`; чтение JSON можно подменить через контракт функции. Не возвращайте сохранение, распознавание и обработку файлов в `App` или JSX-компоненты. Общие модули не должны зависеть от функциональных модулей. Межмодульную координацию размещайте в `app/`. Стили разделены по тем же зонам ответственности; точка подключения — `src/app/styles.css`. Не добавляйте слои CSS-переопределений в конец общего файла.

## Правила предложений

- Каждая запись: `id`, `category`, `bank`, `percent`. Категория и банк обязательны, максимум 120 и 80 символов соответственно; процент — конечное число от 0 до 100. Ручной ввод поддерживает точку/запятую и до двух знаков после разделителя.
- Показывать **все** предложения, включая менее выгодные предложения той же категории в другом банке. Прежнее поведение «только максимальный процент» удалено и не должно возвращаться.
- Пара «банк + категория» сравнивается без регистра и лишних пробелов. Повторное добавление обновляет процент, сохраняя ID. Синонимы категорий и разные варианты имён банков в самих записях автоматически не объединять.
- Предложения на все покупки закреплены наверху и выделены цветом. Остальные предложения идут по убыванию процента; переключатель сортировки удалён по решению владельца. Распознавание формулировок — `src/features/offers/model/categories.ts`; сохраняйте отрицательные примеры вроде «Все супермаркеты» и «Всё для дома».
- Один актуальный набор; нет истории, автоматического истечения срока или очистки при смене месяца.
- Удаление одной записи не меняет другие предложения категории. Полная очистка требует диалога подтверждения.

## Хранилище и перенос JSON

Ключ записей — `cashback.offers.v1`, формат `{ "version": 1, "offers": [...] }`. Не менять ключ или формат без миграции. UI обновляется только после успешной записи. Если исходное хранилище повреждено/недоступно, не затирать его при добавлении или импорте: разрешены повторное чтение или явная очистка. Внешнее событие `storage` перечитывает набор; после ошибки чтения сохранение блокируется.

Экспорт включает все предложения, независимо от поиска, только поля формата. Импорт проверяет весь файл, затем показывает предпросмотр; запись происходит по подтверждению. Неверный JSON/версия/поля/процент или повтор ID отклоняют весь файл. Ограничения — 5 МБ и 10 000 предложений. UTF-8 BOM поддерживается. Импорт объединяет пары; последнее вхождение пары в файле побеждает. Пустой файл не очищает набор. При конфликте ID разных пар назначается новый ID; повторный импорт не создаёт дубликаты. Скриншоты и настройки запуска банков в резервную копию не включаются.

`createId` поддерживает обычный HTTP на телефоне в локальной сети, где `crypto.randomUUID` может отсутствовать. Не удаляйте резервный вариант на `crypto.getRandomValues`.

## Распознавание скриншотов

Поддерживаются PNG, JPEG, WebP, HEIC/HEIF до 25 МБ, включая пустой MIME и проверку сигнатуры HEIC. Выбор файла не должен принудительно открывать камеру. Внешний для bundle, но локальный для сайта `/vendor/heic/heic-to.mjs` — точная копия `heic-to/next` 1.6.6; worker импортирует её через `@vite-ignore` только при необходимости. Не возвращать обычный runtime import из npm: это снова объединит LGPL-код с приложением. Только type-import допустим. Конвертер не переносить в главный JS-пакет или worker bundle; worker должен завершаться при отмене и ошибке.

Совместимый HEIC-модуль можно заменить после сборки без пересборки приложения. Не добавлять SRI, runtime SHA/подпись и immutable-кэш на этот путь. Права на замену/отладку и источники адаптера указаны в `/legal/heic-replacement.txt`. `scripts/vendor/rebuild-heic.mjs <source-folder> <output.mjs>` собирает модуль из upstream JS-исходников; npm ci устанавливает нужное окружение. Свою изменённую библиотеку заменяют в dist после build: prepare проверяет оригинал при официальной сборке. Не считать такую build-time проверку запретом пользовательской замены.

Tesseract использует русские и английские данные с адреса приложения (`public/ocr/`), которые копирует `scripts/ocr/prepare.mjs`. Облачных вызовов нет. OCR загружается динамически. Холст ограничивается 2400 пикселями по длинной стороне; для тёмных экранов используется `PSM.AUTO`, для светлых списков/сеток — `PSM.SPARSE_TEXT`. Предобработка и тестовый CLI используют одну функцию обработки пикселей. Парсер учитывает расположение слов и процентов, сетки, заголовки, дробные значения и символы возле процентов.

Перед сохранением пользователь всегда проверяет и исправляет строки. Отсутствие текста и ошибка распознавания оставляют ручной ввод доступным. Отмена, повторный выбор и закрытие формы должны игнорировать запоздалые результаты; тайм-ауты преобразования/распознавания — 60/120 секунд. Освобождать Blob URL, холсты, worker и обработчики.

## Банки, логотипы и диплинки

Справочники локальные: 300 действующих банков и исторические названия/бренды, 360 WebP-изображений. Поиск использует полные имена и явные aliases, не произвольные подстроки. Не путать разные банки «АТБ»; регистрационный номер — стабильная идентичность. Не переименовывать пользовательские записи при подборе логотипа. Для неизвестного банка или ошибки картинки есть нейтральный значок.

Обновление выполняется только явно:

```sh
npm run banks:sync
npm run banks:apps:sync
```

Эти команды требуют интернет. Источники — ЦБ, НСПК, зафиксированная версия коллекции rblp и официальные сайты. Сведения по каждому изображению сохранены в `scripts/banks/provenance/catalog.json`, по ссылкам — в `scripts/banks/provenance/apps.json` и `scripts/banks/provenance/ios-apps.json`. Не запускать обновление источников автоматически при сборке или открытии приложения. Не удалять атрибуцию в `NOTICE`.

Пользователь явно требует сохранить логотипы; нейтральными значками их не заменять. Реестр `scripts/banks/provenance/logo-rights.json` содержит 360 SHA-256/источников и ограничения проверки (195 НСПК, 126 rblp, 39 сайты банков). Для всего набора разрешения владельцев не подтверждены. В Т-Банке требуется обращение за разрешением; чужая MIT-коллекция не заменяет согласия банка. Не объявлять открытый URL или репозиторий лицензией владельца знака. Обычный `banks:sync` сохраняет текущие картинки; новые загрузки `--images` допускаются только по документированным разрешениям в `scripts/banks/config/logo-permissions.json` с нужным объёмом и сроком. Пока подтверждённых записей нет. Не отправлять письма банкам от имени пользователя без явного поручения.

Кнопки банков показываются только при ширине до 560 пикселей, область нажатия минимум 44 × 44. Названия сопоставляются с 30 популярными розничными банками. На Android используется Intent с известным пакетом и официальным сайтом как fallback. На iOS — явный native URI или банковский Universal Link, обычный пользовательский клик в текущей вкладке; без таймеров, фоновых попыток и подстановки сайта. Исключение по запросу владельца: Совкомбанк на iPhone ведёт напрямую в официальный веб-банк `https://halvacard.ru/lk` (банк перенаправляет на `/lk2`), а на Android сохраняет Intent. В iOS-каталоге это явный `webApp: true`, а не автоматическая подстановка сайта при неудаче нативного запуска. Веб-банк открывается отдельной вкладкой с `noopener noreferrer`, без подсказки «приложение не открылось». Не путать этот признак с HTTPS Universal Link Ozon, который остаётся ссылкой в нативное приложение. Сайт не гарантирует запуск установленной на экран Домой PWA; проверка авторизации банка не выполняется. Ссылка никогда не строится из пользовательского URL и не содержит реквизитов, токенов, оплаты или данных категорий.

Настройка выпуска хранится отдельно в `cashback.bank-apps.v1` как ID из локального каталога. Произвольные URL из localStorage не принимаются. Явный пустой список iOS отключает проблемную кнопку и не должен подставлять корневую схему СБП. Обновление общего справочника не перезаписывает iOS-каталог.

**Ограничения, которые нельзя выдавать за решённые:** регистрация схемы, AASA, строка в приложении и unit-тест не доказывают успешное открытие на физическом телефоне. Для ряда банков остаются непроверенные корни СБП. Сбер/Т-Банк/А-Ключ имеют разные выпуски. Текущие адреса и основания находятся в `scripts/banks/provenance/ios-apps.json`. Для «Сириуса» пустой `sirius://` вызывал зависание; теперь задан полный встроенный маршрут `sirius://siriusapp.com/i/welcomes`. Для ОТП пустой `otp://ru.otpbank.mobile` открывал ошибку, Universal Link `/mobile-bank` открывал сайт; сейчас используется `/toMain` из официального Android-пакета, его поддержка на iPhone ещё не подтверждена. Для Ozon выбран отдельный банковский путь `https://bank-ozon.onelink.me/JbZg/`, не marketplace. Не заявлять все 30 банков проверенными. Пользователь не хочет вручную создавать iOS «Команды».

## Интерфейс и визуальная проверка

Применён выбранный владельцем вариант «Графит»: фон #f2f3f4, белые поверхности, акцент #3c4857, спокойное выделение #e4e8ed, скругления 10 px и собственный знак со стопкой карт. Шрифт Onest (100–900) поставляется локально из `public/fonts/onest-variable.ttf`, без запросов к Google Fonts. Оригинальная OFL — `vendor/licenses/onest-OFL.txt`, происхождение/хеши — `vendor/manifest.json`; prepare и test:licenses проверяют файл и поставку лицензии. Структура экрана сохраняется. Не возвращать красно-жёлтую палитру и логотип-билет из прежнего дизайна.

Главный приоритет — немедленный доступ к категориям. Один экран, компактные карточки с категорией, процентом и банком; без рекламных баннеров, статистики и дополнительных вкладок. Поиск, добавление скриншота/вручную и кнопка «Данные» доступны на телефоне. Минимальная ширина — 320 пикселей без горизонтальной прокрутки; кнопки минимум 44 × 44, формы прокручиваются и не должны зависеть от высоты экранной клавиатуры.

Иконки категорий — локальные SVG из уже используемой Lucide, без внешних запросов. Чистый подбор по русским/английским формулировкам и окончаниям — `src/features/offers/model/category-icons.ts`; отображение — `src/features/offers/components/CategoryIcon.tsx`. Более точные правила стоят перед общими; учитывайте пересечения «корм для животных / продукты», «детское питание / продукты», «Самокат / самокаты», «домашний интернет / дом». Не сопоставлять по произвольной подстроке внутри слова. Для неизвестной категории — нейтральный Tag. Иконки декоративные (`aria-hidden`), название остаётся текстом. Подбор не переименовывает и не объединяет сохранённые категории; менять формат данных не нужно. Сохранять компактные размеры карточек и спокойную графитовую палитру. Иконки используют восемь приглушённых тонов со светлыми подложками (сланцевый, шалфейный, песочный, глиняный, лавандовый, голубой, розовый и бирюзовый); тон задан рядом со значком в `src/features/offers/components/CategoryIcon.tsx`, цвета — в `src/features/offers/components/offers.css`. Фон карточек, названия, проценты и банковские логотипы не перекрашивать вместе с иконками. На телефоне цветная подложка остаётся в прежних 20 × 20 px.

Текущая сетка: три колонки на широком экране, две до 1100 px, одна до 560 px. Карточки на телефоне имеют минимальную высоту 74 px; длинные категории могут увеличить высоту. Не задавать `body` фиксированную минимальную ширину 320 px: при обычной вертикальной полосе прокрутки это создаёт горизонтальное переполнение на окне 320 px. Проверять `scrollWidth <= clientWidth`, включая длинные названия и дробные проценты.

Проверять 320, 375, 390 и настольную ширину, пустое состояние, длинные имена, диалоги, ошибки и предпросмотр. При обновлении README переснимать **реальное приложение** с синтетическими данными; не использовать картинки интерфейса, созданные генератором. Не включать личные скриншоты/финансовые данные пользователя. Эмуляция размеров окна macOS — не проверка Safari iOS или Chrome Android; реальные устройства ещё требуют отдельной проверки.

Скриншоты README воспроизводятся так:

1. Запустить актуальное приложение на отдельном локальном порту с пустым хранилищем и импортировать `docs/screenshots/demo.json` через «Данные». Это 12 вымышленных предложений для демонстрации, а не действующие тарифы банков; не подмешивать их в реальный набор пользователя.
2. Убрать поисковый запрос и закрыть диалоги/уведомления. Снять страницу без рамки браузера: `docs/screenshots/desktop.png` — окно 1440 × 780, `docs/screenshots/mobile.png` — 375 × 812. Оба файла находятся в `docs/screenshots/`. Сохранить исходный PNG без дорисовки интерфейса и проверить его визуально; alt-тексты README должны описывать актуальный экран.

## Проверки перед завершением изменений

После изменений логики/переносов запускать `npm run typecheck`, `npm test`, `npm run build` и `npm run format:check`. При изменениях распознавания, путей ресурсов или подготовительных скриптов — также `npm run test:ocr` (семь синтетических PNG/JPEG/WebP/тёмных/пустых примеров). Тесты расположены рядом с кодом; общий setup — `src/test/setup.ts`. Регрессионные тесты должны проверять пользовательские сценарии и отказоустойчивость, не повторять устройство реализации.

При правках только README, AGENTS и скриншотов достаточно проверки форматирования, ссылок на локальные файлы и корректности демонстрационного JSON; не выдавать прежний запуск тестов приложения за выполненный заново.

Для браузерной проверки использовать отдельный локальный порт и только синтетические данные. Не читать и не перезаписывать реальный набор пользователя. Не обходить запреты браузера на native URI или предупреждения сертификатов банков. Скачивание JSON и его обратный импорт проверять настоящим файлом. После проверки удалять только созданные тестовые записи и закрывать временные вкладки. Не утверждать успешный нативный запуск по DOM href.
